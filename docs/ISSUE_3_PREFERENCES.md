# Camera preferences (#3)

The app explicitly injects `UserDefaultsCameraPreferencesStore(defaults: .standard)` before constructing the initial camera UI. The versioned app-owned key `LittleMoments.cameraPreferences.v1` contains JSON with only `duration`, `audio` and `camera`. Fresh defaults remain 30 seconds, audio on and rear camera. The User Defaults privacy reason is CA92.1; all three earlier manifest categories remain present.

Each field decodes independently. Missing or invalid values use that field's default; unknown fields are ignored. A malformed top-level record uses all defaults. Add backward-compatible feature options as typed, defaulted fields in `CameraPreferences` and its tolerant decoder. Retain the v1 key when adding fields; an incompatible representation needs an explicit migration to a new key. Older binaries ignore unknown keys and may drop those unknown fields when saving, so this is forward-readable rather than a cross-version lossless document format.

`CameraModel.updatePreferences` is the single update/persistence boundary for current and future choices. It rejects edits during startup, capture and stop transitions, validates the typed value, publishes accepted choices and saves them together. Duration and audio controls use explicit setters; camera switching follows the same path. A storage failure leaves the current in-memory choice usable and reports that it will not survive app closure. Loading never requests permissions or starts capture. Phase, operations, grants, clips and active recording are never encoded.

Model tests use a fresh in-memory store unless explicitly injecting a disposable UserDefaults suite. DEBUG UI-test launches reset the disposable `org.littlemoments.UITests.Transient` domain. A relaunch test can instead supply `--uitest-preferences-suite=org.littlemoments.UITests.<unique-id>` and `--reset-uitest-preferences` on its first/cleanup launches; a plain relaunch retains only that isolated domain's choices. These test arguments never apply to Release builds.

Verification selectors: `LittleMomentsTests/PreferenceTests` and `LittleMomentsUITests/PreferenceUITests`. Coverage includes defaults, durable round trips, independently invalid fields, missing and unknown fields, corrupt records, storage failures, guarded updates, isolated domains and a full UI relaunch with a stopped camera. Run the existing `CameraModelTests` cancellation/permission coverage and source, built-app and unsigned-archive privacy checks alongside them. iOS execution requires Xcode/macOS; Linux static verification does not establish an iPhone runtime result.
