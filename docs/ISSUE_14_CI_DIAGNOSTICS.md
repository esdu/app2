# Issue #14 — recorder stress and failure evidence

The ordinary `test-without-building` pass runs every unit, integration, and UI test once. Three additional passes reuse those products and select `CameraModelTests`, `MediaIntegrationTests`, and, when the production harness source exists, only its short rollover/snapshot and delayed-completion cases. The five-minute retention/window/audio matrix runs in the ordinary pass only. UI tests are excluded from repeated passes.

`scripts/run_ci_tests.py` stops on the first nonzero `xcodebuild` exit. There is no retry-until-pass or success override. Each pass writes its own `LittleMoments` or `Stress-N` result bundle, log, and status JSON, including a started state before launching the subprocess. A killed/timed-out process can therefore leave an incomplete state and unknown counts without fabricating a pass. A renamed harness stress method fails selection visibly instead of silently dropping coverage.

The always-run diagnostics step publishes a preliminary status/log summary before extraction, then uses Xcode 16's `xcresulttool get test-results summary`, retaining the raw JSON/stderr and falling back to the legacy invocation record when needed. It preserves counts, failure names/messages, Xcode version, selected device/OS, and the evidence artifact name/run link in the Actions summary and `test-summary.{md,json}`. Missing or malformed result counts remain `unavailable`. Per-run attachment/diagnostic exports have bounded command timeouts; failures become evidence warnings and retain partial output. Readable `.crash`/two-object `.ips` reports, including reports inside exported device ZIPs, contribute a short crashed-thread stack. No exported crash report does not establish that no crash occurred.

Only diagnostics have `continue-on-error`; build, ordinary tests, stress tests, and archive/privacy checks retain their original failure behavior. Extraction commands have 15-second summary / 30-second export limits, and the diagnostics step is capped at six minutes. The Intel runner, read-only repository permission, 40-minute job budget, unsigned build/archive, source/built/archive privacy checks, simulator screenshot/logs, and always-run artifact upload remain in place. Artifact paths are now `diagnostics/<run>/attachments` and `diagnostics/<run>/diagnostics` so iterations cannot overwrite one another.

Local validation: `python3 -m unittest discover -s scripts/tests -v` covers mocked modern success/failure schemas, legacy wrappers, unavailable/malformed inputs, incomplete bundles, failed exports, partial extraction timeouts, `.ips`/ZIP crash reports, bounded selection, and an actual fake `xcodebuild` subprocess exiting 65. The fixtures explicitly identify synthetic evidence. A macOS Actions run is still required to validate real Xcode exports and runtime/budget behavior; Linux cannot execute `xcrun` or simulator tests.
